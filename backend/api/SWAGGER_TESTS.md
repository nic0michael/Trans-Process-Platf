# Test Procedure

## Swagger URL

### Description: -

Swagger provides the REST API interface used to execute the manual API tests.

### Request: -

Open:

```text
http://localhost:8080/swagger-ui/index.html
```

### Procedure: -

1. Start the Spring Boot API:

```bash
./gradlew :backend:api:bootRun
```

2. Open the Swagger UI in a browser:

```text
http://localhost:8080/swagger-ui/index.html
```

3. Locate the transaction REST endpoints.
4. Use **Try it out** to execute each test in this document.

---

## Test 1 - Create a Purchase Transaction

### Description: -

Submit a valid purchase transaction through the REST API.

This is the first transaction used to establish the REST → Kafka → database test flow.

### Request: -

```json
{
  "timestamp": "2026-09-20 10:00:00",
  "transactionIndex": "100001",
  "transactionGuid": "",
  "requestId": "11111111-1111-4111-8111-111111111111",
  "externalSystemId": "WEB_PORTAL",
  "transactionType": "PURCHASE",
  "currency": "ZAR",
  "amount": "1250.50",
  "reference": "TEST-PURCHASE-001",
  "transactionDescription": "Swagger purchase test",
  "companyId": "1001",
  "status": "PENDING"
}
```

### Procedure: -

1. Open the POST transaction endpoint.
2. Select **Try it out**.
3. Paste the request above.
4. Execute the request.
5. Verify the response code is `200`.
6. Verify the response message is:

```text
Transaction sent to Kafka
```

7. Verify that the response contains a generated `transactionGuid`.
8. **Record the `transactionGuid` received from this test in a notepad.**
9. This GUID will be used in **Test 2**.

Expected response structure:

```json
{
  "responseCode": "200",
  "responseMessage": "Transaction sent to Kafka",
  "timestamp": "2026-09-20 10:00:00",
  "transactionIndex": "100001",
  "transactionGuid": "<GUID GENERATED BY SYSTEM>",
  "requestId": "11111111-1111-4111-8111-111111111111",
  "externalSystemId": "WEB_PORTAL",
  "transactionType": "PURCHASE",
  "currency": "ZAR",
  "amount": "1250.50",
  "reference": "TEST-PURCHASE-001",
  "transactionDescription": "Swagger purchase test",
  "companyId": "1001",
  "status": "PENDING"
}
```

## GUID Test Rule

### Description: -

Transaction GUIDs are generated by the API. They must not be manually supplied for new transactions.

### Request: -

Every new transaction request must contain:

```json
"transactionGuid": ""
```

### Procedure: -

For every test that creates a new transaction:

1. Set:

```json
"transactionGuid": ""
```

2. Submit the request.
3. Read the `transactionGuid` returned by the API.
4. **Record the GUID in a notepad.**
5. Use that exact GUID in the next GET test.
6. Do not replace the generated GUID with another GUID.

This provides a traceable test chain:

```text
POST Request
     |
     v
Generated GUID
     |
     +----> Record in Notepad
     |
     v
GET using GUID
     |
     v
Database Record
```

## Validation Fields

### Description: -

The following fields are mandatory and are validated by the transaction validator.

### Request: -

The validation tests use empty strings for the field being tested.

`transactionGuid` remains empty for new transaction requests.

### Procedure: -

The mandatory fields are:

```text
timestamp
requestId
externalSystemId
transactionType
currency
amount
reference
transactionDescription
companyId
```

The following field is intentionally kept empty when creating a new transaction:

```text
transactionGuid = ""
```

The following field is not part of the supplied mandatory-field validation:

```text
transactionIndex
```

The validator messages are:

```text
Timestamp is missing
RequestId is missing
ExternalSystemId is missing
TransactionType is missing
Currency is missing
Amount is missing
Reference is missing
TransactionDescription is missing
CompanyId is missing
```
